# L1 design note: the hub learns its owner

- Contract: `.ade/context/learn.md`. `bin/learn` is the bash front (hub, user, folder, terminal checks, editor, the
  forget prompt); `bin/learn.py` (`python3 -I`) parses, validates and writes, under one flock in the state dir, with
  atomic replaces.
- Every write rebuilds the person's `MEMORY.md` from the files, so the index cannot drift from them. `log.md` is only
  ever opened for append.
- A capture is refused before anything is written: the cheap checks (characters, email, phone, length) first, then
  `gitleaks stdin`, the scanner the pre-commit hook and `bin/sync` already rely on. No gitleaks, no capture.
- The load re-checks each rule line (not gitleaks: it runs at every session start), because the files can be edited by
  hand or by an agent's own Edit tool; such an entry is skipped and counted, not printed.
- The role reaches the session's hooks as `AGENT_ROLE`, exported by `bin/work`'s launcher (unset when there is none),
  next to the `AGENT_FOLDER` it already sets.
- A repeat is an exact match after normalising; anything subtler is L2's weekly review.
- Not done here: a Claude Code ask rule for edits under `memory/users/` (the settings template is another story's file
  right now); `ade` commands.
