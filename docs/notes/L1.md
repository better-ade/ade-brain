# L1 design note: the hub learns its owner

- Contract: `.ade/context/learn.md`. `bin/learn` is the bash front (hub, user, folder, the person-only gate, editor,
  the forget prompt); `bin/learn.py` (`python3 -I`) parses, validates and writes, under one flock in the state dir, with
  atomic replaces. Every write rebuilds the person's `MEMORY.md`; `log.md` is only ever opened for append.
- Fix round (2026-11-22, the adversarial review): a planted entry took effect in every later session unseen. Now every
  capture waits until the person confirms it at their own terminal, and the confirmation (a sha256 of scope and rule
  line, or of a profile fact) lives in the state folder outside the checkout, so a file written by hand, edited, or
  synced in from elsewhere waits again. The hash leaves out the counters, so a repeat stays confirmed.
- The person-only commands (confirm, edit, forget) refuse in an agent session using one list of session variables in
  `bin/lib.sh` (`agent_session_vars`), which `bin/work`'s launcher now also unsets.
- A capture is refused before anything is written: character, contact, number and token checks, the markup/link/tripwire
  checks for what loads, lengths, then `gitleaks stdin`. The load re-checks each entry the same way (not gitleaks: it
  runs at every session start) and counts what it skips.
- What this does not stop: an agent with the person's shell can forge the confirmation file. The ask rules in both
  settings templates and the briefing's list of what was learned and what waits are the answer to that, not a promise.
- A repeat is an exact match after normalising; anything subtler is L2's weekly review.
