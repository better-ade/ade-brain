# H2 design note: the hub's key store runs ade-secrets

- `bin/secret` takes ade-secrets' delegation block (contract v1, tag v0.3.0) word for word on the line after `set -u`,
  before `bin/lib.sh` is sourced: while delegating, nothing of the hub's own store (or `hub.conf`) is read. The
  `set -u; . lib.sh` line was split in two for that.
- `secret_delegated` in `bin/lib.sh` repeats the block's test so `bin/keys` and `bin/doctor` agree with `bin/secret`.
  `bin/keys` skips its store check while delegating and turns a refused presence check (exit 3) into "run this in your
  own terminal" (exit 3); without ade-secrets its presence check is the old one, so its behaviour is unchanged.
- `HUB_SECRETS` already existed in `hub.conf` (bin/init writes the secret names bin/doctor checks). Sourcing `hub.conf`
  would overwrite an exported `HUB_SECRETS=builtin` and pass the names on to `bin/secret`, which would then delegate.
  `bin/lib.sh` now reads hub.conf's value as `HUB_SECRET_NAMES` and restores the environment's value. Existing hubs'
  `hub.conf` files need no change. The switch is environment-only (as in the contract) and in `checkout_gate_vars`.
- Tests never reach a real ade-secrets: `make_hub` drops every `PATH` folder holding one (a test's fake is kept by
  `ADE_SECRETS_FAKE_DIR`). Without that, installing ade-secrets would put the whole suite on the real store.
- Not done here (other stories): the hub reads values outside the key helper in `provider_key_ok`,
  `anthropic_key_ok`, `gemini_auth read`, `bin/gemini-run` and `bin/chat` (the Telegram token). ade-secrets' `get`
  serves only Claude Code's key helper, so with ade-secrets installed those reads are refused.
