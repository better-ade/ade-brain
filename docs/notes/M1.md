# M1 design note: an ALERT wakes the monitor role

- Polling stays model-free. The triage runs inside bin/monitor's loop, right after the existing new-ALERT transition,
  so "once per alert" reuses the `<key>.alert` state and cannot drift from what is journaled.
- bin/agent is unchanged: read-only tools, its own nonce frame and its own AGENT_TIMEOUT cap. bin/monitor adds a second
  frame (its own nonce) around the monitor output in the task, so the alert text is marked untrusted before the model
  sees it.
- The verdict that reaches the journal and the notification is one line of model output (control characters
  removed, 200 characters at most). It is data, like every bin/agent report.
