# R1 design note: crash-proof continuity

- One script, `bin/recover`, owns every repair; `bin/doctor` calls `bin/recover --check` so the checks cannot drift
  apart. Each repair is small and only removes what is provably dead (a pid that is gone, a lock whose owner is gone,
  bytes after the last newline); work in checkouts is listed, never touched.
- A dead agent is detected from its session entry: bin/work's launcher removes the entry on a normal exit, so an entry
  whose launcher is gone means it was killed. bin/sessions used to delete those entries; it now moves them to
  `sessions-dead/` so recover still sees an agent that died before recover ran.
- Its ticket is marked `blocked` (reason "agent died") through the BMAD runtime's `tickets mark`, and main is notified
  with a note starting "blocked:", which the C7 status card shows as ⚠ blocked.
- "Login expired" cannot be detected directly; a crash loop (3 service starts in 10 minutes, launchd's throttle is
  60 s) is the signal, and the job disables itself so launchd stops retrying.
- Rows the code here does not cover: Linux/systemd (V1), tmux (not used; agents are separate processes from any UI).
